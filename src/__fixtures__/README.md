# Frozen v1 vault fixtures

These are real v1-format vaults generated by the **current** `src/crypto.js`
(before any v2 changes) using `scripts/generate-fixtures.mjs`. They exist
to prove that v1 vaults remain unlockable for the life of the project —
real users have v1 vaults on real devices, and nothing may make them
unopenable.

## Files

| File | PIN | KDF iterations | Notes |
|------|-----|----------------|-------|
| `vault-v1-100k.json` | `123456` | 100,000 | Legacy format (pre-hardening) |
| `vault-v1-600k.json` | `654321` | 600,000 | Current v1 format |

## Format

Each fixture is a JSON object:

```json
{
  "pin": "123456",
  "iterations": 100000,
  "docs": [ ... ],
  "imgs": { ... },
  "emergency": { ... },
  "storage": {
    "vid_salt": "<base64>",
    "vid_vault": "{\"iv\":\"...\",\"ct\":\"...\"}",
    "vid_updated_at": "<ISO>",
    "vid_dirty": "0"
  }
}
```

- `pin` / `iterations` — how to unlock the vault.
- `docs` / `imgs` / `emergency` — the plaintext that was encrypted (for
  verifying a successful unlock returns identical data).
- `storage` — the exact localStorage state. Tests load this into their
  in-memory stub, then call `tryUnlock(pin)`.

## Regenerating

```bash
node scripts/generate-fixtures.mjs
```

**Warning:** regenerating produces new random salts and IVs, so the
fixtures will differ each run. Only regenerate if you intentionally want
to rotate the test vaults — the committed fixtures must stay stable so
tests are reproducible.

## Security note

The PINs (`123456`, `654321`) and all data in these fixtures are **fake
test data**. They are not real vaults and contain no real PII. The
documents use masked numbers (`XXXX XXXX 4521`) and the image is a 1×1
transparent PNG.
